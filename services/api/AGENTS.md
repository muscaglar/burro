# services/api

Burro's HTTP API: FastAPI over one data release held in memory. It has one database, the file of accounts, which is opened only where accounts are turned on: "Accounts", below. It is built to [docs/design/contract.md](../../docs/design/contract.md), sections 8 to 11, at contract version 3; if the two disagree, change one of them in the same commit.

```
make api                     run it on this machine, on the synthetic release, at 127.0.0.1:8000
make openapi                 rewrite contracts/openapi.json after a route or a record changes
make test ARGS="-m full"     run the generated tests in full, which `make ci` samples
```

Settings come from the environment: `BURRO_RELEASE_DIR`, `BURRO_CENSUS_DIR`, `BURRO_CENSUS`, `BURRO_MODEL_TIMEOUT_S`, `BURRO_MODEL_MAX_TOKENS`, `BURRO_MODEL_CALLS_PER_MINUTE`, `BURRO_MODEL_CALLS_PER_DAY`, `BURRO_HOST`, `BURRO_PORT`, `BURRO_ALLOWED_ORIGINS`. With none set it serves the committed synthetic release with the rule-based interpreter, to a browser on `http://localhost:3000` and no other. Which provider of a model reads what is typed, if any, is not a setting of `Settings`: `providers.choose` reads `BURRO_MODEL_PROVIDER`, that provider's key, `BURRO_MODEL_TERMS_ACCEPTED`, `BURRO_MODEL_ID` and `BURRO_MODEL_SENDS_SETTINGS`, once, as the service starts. Which way gritty is built is the release's to say, and there is no setting for it: to serve the other way, build it with `burro-release build-synthetic --gritty a --out FOLDER` and name its folder in `BURRO_RELEASE_DIR`. The settings of accounts are read only where `BURRO_ACCOUNTS` says `on`, and are listed under "Accounts".

## Privacy comes first

Raw prompt text and destination strings are never written to a log, an exception message, an error response or a call record (ADR 0005). This is kept by construction. Do not weaken any of these to make a change pass.

- **Logs.** `logs.event()` is the only way a line is written, and `logs.log_failure()` the only way an exception is, at the level of an error. A field that is not in `LOGGABLE` cannot be logged. No message is ever formatted, and a library's record is cut down to where it came from. Never call `logging` directly, never `print`, never `str(error)`.
- **Nothing of a spec.** No hash of a spec is logged or kept, plain or under a key, and nothing else that is worked out from one. The plain hash gives the spec back to anyone who can try specs, and a keyed one confirms a guess for whoever reads the log and can call the service. `spec_hash` goes in a response and nowhere else. There is no key in the service: do not add one to tell two calls apart without a new decision (ADR 0011).
- **Errors.** `message` is fixed text for the code. `fields` is built from pydantic's `loc` and `type` only, and a part of a path is kept only if it is one of our own field names: those of the bodies of the search, and for a route of accounts those of the bodies of accounts too (`KNOWN_NAMES`, `KNOWN_TO_ACCOUNTS`). A route of the search keeps no name of accounts and takes no code from one, so it answers as it did before there were accounts. Raise `ApiError` with a code; never put a value in it.
- **The edge.** `boundary.Boundary` catches whatever a route lets fall and answers 500. It never raises again, because the server would print the message. The server's access log is off; the request line names the route template, never the path. No response is a redirect: `redirect_slashes` is off, because a redirect repeats the path in a header.
- **The model.** Only `reader.py` sends a person's words anywhere, and only to the model. They go alone unless `BURRO_MODEL_SENDS_SETTINGS` is `yes`: then the search goes with them, without where a journey leads. The reader and the notice are made from the one setting, so what people are told is sent is what is sent. A failure leaves as a `ModelFailure` with no message and no cause. **`answer` in `routes/interpret.py` is the edge for whatever else the path of a model raises, of any kind**: a provider's error can hold the sentence and the key, so it is never raised again, and what is written of it is its type and its frames. It reaches neither `Boundary` nor the server. `tests/providers/test_failed.py` drives each way of failing with a marker in the sentence and a made-up key: a new way gets a case there. `destination_text`, `area_text` and `words` are what a model copied from the person: each is held in a field that no `repr` shows, looked for in the text and dropped. What is withheld from a model's answer is counted and never named. The model is never sent a name of the release, and is never asked where a place is.
- **Where the words stand.** `rests_on`, `suggestions`, `unread` and `unmet_at` are served by route 1 to the caller, who holds the text: offsets, never words. So are `spans`, `shown` and `named_at` of an offer. None is ever logged, counted in a line, kept about a call or stored in a share, and no other route takes or returns one. `logs.LOGGABLE` and `CallRecord` have no field for any, and a test says so. A suggestion's label is the release's name or the catalogue's, never the text.
- **The name of a place.** `places` names each place of a spec that is returned, and `place` the place of a journey's row of a comparison. A name says where someone works as its id does: it is worked out when the answer is made, served in the body, and logged nowhere. It is kept in one place, where accounts are on: the name of a search that is kept holds the release's name of each place its journeys lead to, beside the spec and under the same account (`accounts/names.py`, ADR 0044).
- **What a browser holds.** `If-None-Match` is compared with the tag the service gives, which names what made the answer: the id of the release, and eight characters that change with the release as it was loaded, with the engine and with the contract (`made_of` in `deps.py`, `release_headers` in `routes/common.py`). The id alone is not enough: the made-up city keeps its id however often it is built again, and a browser that held what an earlier service gave was told that it still stood. **A change to a word that routes 4, 5, 6 or 11 serve is published under another version of the engine or of the catalogue than the one before it, or a browser that came before keeps the old word.** What was sent is never logged, and what is sent back is the service's tag and never the header. `tests/test_an_answer_that_still_stands.py` holds it.
- **Text in bodies.** Anything a person types travels in a `POST` body. A path holds an id from the release or an opaque share id. There are no query parameters.
- **Tests.** `tests/test_privacy.py` plants a canary in every route and every failure path, and looks for it in every log record, every line, standard output, every call record and every response. A new route or a new failure path gets a case there before it is merged.
- **What route 1's line depends on.** Its counts of edits and of rejections, and its codes of what was assumed and unmet, depend on the words and the spec together. They hold no id, no name and no number. Whether to go on logging them is an open point of the contract (section 13) and is not yours to settle by adding a field.

## Rules

- `Deps` holds everything a test may need to fake. A route reads the release, the clock and the ids from it, never from a module or the system.
- Ranking, the reducer, facts and the verifier live in `burro_core`, and so do bands, likeness, the portrait and the strip. A route calls them; it never works out a score, a percentile, a band or a sentence of its own. If a route needs arithmetic, the arithmetic belongs in core.
- The vibes a route names are the release's, `release.vibes`, and never `TAGS`: a release carries one way of gritty and not both.
- A vibe is shown as a band, one of five. `bands` of route 4 and `character` of route 7 hold bands and no score, and a `tag:` row of a comparison holds no percentile. Route 6 serves the rows of `tags.json` as the release holds them, `score` and `raw` among them: they are for ranking, no fact holds them, and a client never prints them. `distance` of a likeness is never served.
- Never import `burro_pipeline`. The API and the pipeline meet at the release folder. `loading.py` reads bytes and leaves every check to `open_served` in core.
- A release that is not made up is served only with the folder its build wrote beside it, `ID-build`, which holds `hashes.json`, `evidence.json` and `lock.json`. `loading.py` reads their bytes and core holds each to its hash. The service reads nothing of the evidence. It refuses to start on a release that lacks one of the three, or whose manifest, evidence or lock has changed since the build. See ADR 0018.
- Nothing imports a provider's library, and the service depends on none. Each adapter in `providers/` makes one HTTPS call with the standard library. A test checks the imports, the manifest and what is loaded when the service starts.
- A route is declared with its whole path (`/v1/...`) on its own router. `boundary.py` matches against the routes as declared, because how the framework nests included routers has changed between versions.
- Every response that holds data from the release carries `meta.synthetic` and `meta.preview`, and the headers `X-Burro-Synthetic` and `X-Burro-Preview`. Errors too. The first says the figures are made up. The second says the release is not finished, whether its figures are made up or real. A 304 and a 204 have no body, so the headers say both alone.
- Routes 4, 5, 6 and 11 are a function of the release alone. Each calls `of_the_release`, which sets `Cache-Control: no-cache` and the `ETag`, and answers 304 where the caller holds the loaded release. Call it after anything that may refuse, so that a 404 is never said to stand. **The tag names what made the answer**: the id of the release, and eight characters that change with the release as it was loaded, with the engine and with the contract (`made_of` in `deps.py`, `release_headers` in `routes/common.py`). The id alone is not enough: the made-up city keeps its id however often it is built again, and a browser that held what an earlier service gave was told that it still stood. So a change to a word that one of these routes serves is published under another version of the engine or of the catalogue than the one before it, or a browser that came before keeps the old word. `tests/test_an_answer_that_still_stands.py` holds it.
- One document cannot hold two records of one name. A record of core whose name another record has is given a name of its own in `wire.py`, field for field, as `SuggestionChoice` is. A test refuses a schema named for a module, or once for what is sent and once for what is served.
- Missing data is `null`, never zero. Nothing is filled in on the way out.
- Every list of areas says what is known of each name: `named` of `AreaSummary` is core's record, served as the release holds it, and `null` for an area that bears no name but its label. A route chooses no name and words no state. Route 8 finds areas as well as places, and lists them apart, because an area is no place to reach: it is never handed to a journey.
- A ranking says how many areas are ranked and how many of them it lists (`areas_ranked`, `areas_listed`), so that a list which stops short never reads as the whole. An area that is listed apart for want of data is served as core gives it, with its reason and what it lacks, and is in no score.
- A comparison has one row for each journey, named as core keys a journey, with the same place across the row. A journey with no time has a cell that cites its `missing` fact. What the journeys add to the fit is core's one figure: it stands beside the journey that drove the score, and is never shared out between journeys here.
- `contracts/openapi.json` is generated and committed. A test fails if it is out of date: run `make openapi`.
- A route of the search knows nobody. `identify` and `admit` in `app.py` are the places kept for who asks and for what one caller may ask of a search, and both are empty. Who is signed in is known to the routes of accounts alone, by `accounts/gate.py`. Do not read a session, a cookie or an address in any other route without a new decision.
- **Calls to a model are capped, for the whole service and for no one caller** ([ADR 0032](../../docs/adr/0032-calls-to-a-model-are-capped-for-the-whole-service.md)). `cap.py` counts the calls of the minute and of the day that are running, in UTC, in memory. `ModelInterpreter.interpret` asks it as a call is about to be made, and raises `ModelCapped` where a cap is reached, so that the route answers as it does where a provider says that it is capped: 200, by the rules. **`Cap.lets_in` is handed nothing: no address, header, cookie or token is read, hashed or kept, and a test says so.** `deps_from` always hands the reader a cap, and at nought makes no reader of a model at all. Do not answer 429, do not count in `admit`, and do not tell one caller from another without a new decision.
- A request body is a `wire.Body`, and is listed in `wire.BODIES`, or in `accounts.wire.BODIES` where it is a body of accounts. A number in it must be sent as a number: `Body` refuses `true` and `"0.5"` where the validator alone would read 1 and 0.5. A body may hold a field that is a number or `null`, and no other choice of types; a test says so. A model's answer is a `Body` too, so `true` is never position 1.
- A route that takes edits applies them first and checks the spec they leave, so a spec that names what the release has dropped can be put right by the edit that takes it out.
- The origins a browser may call from are a list in `Deps`, compared exactly. `Boundary` answers for them on every response, its own refusals included. Never a pattern, never `*`, never credentials: no browser is ever let send a cookie across origins, with accounts on as with them off. An entry that no browser would send, `https://burro.example:443`, is refused when the service starts, because it would match nothing and nobody would be told. Do not add the framework's CORS middleware beside it: it answers a browser it refuses outside the error envelope.
- **The census is read by one route.** Route 13, `routes/census.py`, serves the census figures of one area, and `offer()` gives route 11 the words of the block that offers them. Nothing else reads `Deps.census`: not a route that ranks, explains, compares or shares, not the reader, and not a log line. The route takes one area and nothing else, so a query of any kind is refused, and no route serves the census of more than one area. It works out no figure: what is served of a row is core's `panel()`. Its answer is `no-store` and `noindex`. `tests/test_census.py` tries every way in, and serves two services the same searches with the figures moved between areas. Do not add a field of the census to another route, a body or a line: changing that is changing ADR 0014.
- **Household income is read by one route.** Route 14, `routes/income.py`, serves what the households of one area are estimated to have, and `offer()` of core's `income.py` gives route 11 the words of the block that offers it. Nothing else reads `Deps.income`. No route ranks on it, compares on it or explains by it, and `tests/test_income.py` holds each by itself: the answers of routes 2, 3 and 7 are the same, byte for byte, with every area's figures handed to the next area and with none served. It is found as the census is: beside the release, in a folder named for it with `-income` after, or where `BURRO_INCOME_DIR` says. `BURRO_INCOME=off` serves none.
- The census stands beside the release, in a folder named for it with `-residents` after. `loading.py` reads its bytes and leaves every check to `open_census` in core. A folder that is not there is no census, unless `BURRO_CENSUS_DIR` named it. `BURRO_CENSUS=off` serves none.
- **What one sentence costs is held.** Route 1 is open to anybody and nothing limits what one caller asks, so no sentence it takes may hold the processor for long. The rules read a clause once while an answer is made, however many places of an offer stand in it: `_read_alone` in `guard.py` keeps what they made of each, for that answer and no longer. Whether a turn leads up to a thing is read once for the thing, however many things are listed after it: `Typed._is_led_by_a_turn`. What is said of a thing is read by the rules once, however many things stand in it, and a part of a sentence is asked once what it may say of a thing beside it, however many things its sentence holds: `_Sayings` in `guard.py`. `tests/test_a_name_said_over_and_over.py` holds the sentences the service was driven with to two seconds of processor, where they are read in a fifth of one and a plain sentence in a few thousandths, and holds what made each slow by counting. Do not ask the rules again for each place an offer points at, ask nothing of every thing of a sentence for each thing of it, and give a sentence that is found to be slow a case there.
- `CallLog.add` lets go of what is too old, wherever it stands in the log. Nothing in the service reads the log, so a log that expired records only on reading would expire none.

## Accounts

Signing in by a link sent by email, and what a person keeps under an account ([ADR 0043](../../docs/adr/0043-burro-has-accounts-and-a-person-signs-in-by-a-link-sent-by-email.md), [0044](../../docs/adr/0044-a-person-who-has-signed-in-may-keep-a-search-and-what-is-kept-is-the-spec-and-never-the-words.md) and [0045](../../docs/adr/0045-the-service-has-a-database-one-file-for-accounts-and-what-they-keep.md), contract section 9.8, and [the design of accounts](../../docs/design/accounts.md)). **They are off until they are turned on.** Do not weaken any of these to make a change pass.

- **Off is what the service was.** With `BURRO_ACCOUNTS` unset or `off`, `Deps.accounts` is `None`: no route of accounts is served, no file is opened, no setting of accounts is read, and no answer of any route differs. `tests/accounts/test_off.py` and `test_start.py` ask every route and listen for every file that is opened. The contract lists the routes either way.
- **The website alone is heard, before anything is made of what was sent.** `accounts/gate.py` is the kind of route every route of accounts is: it hears the secret of the website, in constant time, and for what changes anything the `Origin`, `X-Burro-Request: 1` and the content type. A new route of accounts is declared on the router of `routes/accounts.py`, and is then held to all of it by `tests/accounts/test_gate.py`, which reads the routes from the router.
- **The address of a client is one header, from the website, with every request.** `accounts/limits.py` reads nothing else that names an address. A request that names none, or one that cannot be read, is refused as not the website's, anywhere but in development. It is counted under a keyed hash, in memory, and is written nowhere. Never log it, never keep it, and never read `X-Forwarded-For`.
- **Asking for a link looks for no account, and waits on no letter.** The answer and the work are the same whether or not the address has an account, and whether or not it is over its limit and is sent nothing: the route hands the letter to `Accounts.send` once the answer has been given. `test_sign_in.py` holds the answer byte for byte, the statements that are run one for one, the order of the answer and the letter, and the time by measuring. Do not add a look-up of an account to `_link_to`, and do not send from it.
- **One layer touches the file.** `accounts/store.py` holds every statement, written out, with every value bound. None is ever built: a test reads the file and refuses a statement that is. Every look-up of what is kept names the account, which the session gives and no request can.
- **What is kept of a token and of a session is its SHA-256.** Never the token. A session is always made anew.
- **A search that is kept is the spec.** It is checked by `check_spec` before it is kept and by the schema when it is read. Its name is `accounts/names.py`'s, from the spec and the names of the release. No body of accounts has a field for what was typed but `email`. No hash of a spec is made.
- **A line of the log says what happened and how it ended**, each a word of `accounts/events.py`. `tests/accounts/test_log.py` drives everything that can happen to an account and looks for every address, token, session, id and secret that was used, and for anything in the shape of one. A new thing that can happen is driven there.
- **A failure to send carries no message.** What goes wrong underneath can hold the address, the link or the key of the sender.
- **No id is in a path.** A search or a session is named in a body. No route of accounts takes a query.

| Setting | What it is |
|---|---|
| `BURRO_ACCOUNTS` | `on` turns accounts on. Unset, or `off`, they are off. Any other word stops the service |
| `BURRO_ACCOUNTS_DB` | The file accounts are kept in. Its folder must be there |
| `BURRO_ACCOUNTS_SITE` | The origin of the website, which a link leads to. It is one of `BURRO_ALLOWED_ORIGINS`, and is `https` unless the service is in development |
| `BURRO_WEBSITE_SECRET` | What the website is known by: 32 characters or more. The website holds the same |
| `BURRO_ACCOUNTS_LIMITS_KEY` | The key the addresses of clients are counted under: 32 characters or more, and not the secret of the website |
| `BURRO_ACCOUNTS_SENDER` | Who sends a link: `postmark`, `resend`, or `console` in development. With none named, asking for a link answers 503 |
| `BURRO_ACCOUNTS_SENDER_KEY`, `BURRO_ACCOUNTS_SENDER_FROM` | The key of the company that sends, and the address a link is sent from. Needed where a company is named |
| `BURRO_ACCOUNTS_DEVELOPMENT` | `yes` says that the service is being developed. It is refused unless `BURRO_HOST` is the machine's own address. It allows the website in the clear, cookies under their plain names, and the sender `console` |
| `BURRO_ACCOUNTS_LINKS_PER_HOUR` | How many links the whole service sends in an hour: 200 unless it is set, and 10,000 at the most |
| `BURRO_ACCOUNTS_KEEP_RECENT` | `asked`, which is what stands, or `from_the_start`: whether a person's last searches are kept before they have chosen |

**Neither company that sends has been run against.** `accounts/sender.py` is tested against a function that answers in the company's place, as each adapter of a model is.

## The model-backed interpreter

**A key alone turns nothing on.** A model reads what is typed only when `providers.choose` says so: a provider is named, its key is present, its terms are accepted by naming it, and the model is one its adapter was fitted to. DeepSeek never reads what people type, whatever is set. With any of them missing the rules read, and the service says in one warning, as it starts, which provider is not used and which is missing. The line holds two fixed words and never a thing that was set. [docs/design/models.md](../../docs/design/models.md) has the whole of it.

`deps_from(settings, choice)` takes the reader and what people are told from the one `Choice`, and a `Deps` cannot be made that tells people other than who reads. `Settings` holds nothing of a provider. The reader is tested against a fake `ModelClient`, and each adapter against a function that answers in its provider's place. **No test calls a provider, and no adapter has been run against a live API.** Before relying on one: measure it on the evaluation set, and check that the schema in `reader.SCHEMA` is accepted as it stands.

**The model proposes, the person confirms, code checks** (ADR 0012, contract section 8.2). The rules read first. A plain prompt is applied by the rules, and no call is made. For any other prompt the model is asked, what it says becomes offers, and the two are merged: one offer for each thing, so that a person never sees less than the rules alone give.

- **A prompt the rules applied is handed to no model, whatever is unread of it.** `asks_a_model` in `reader.py` is the one rule. The answer that follows a call holds no edit, so a prompt that was handed on lost what the rules applied of it: of "leafy, a flat", typed by a renter, the wish for leafy. A journey to a place that is yet to be chosen is a question, and is no edit that was applied. The answer that follows a call holds no question either: the words it rested on are said to be unread, unless an offer rests on them, so that no journey is dropped without a word.
- **Nothing a model reads is applied.** Every edit of `operations` is the rules' own. What a model read is in `suggestions`, and moves nothing until a person presses it. This is a test and not a rate: `test_no_edit_of_a_models_is_applied_whatever_it_answers`. Do not add a path that applies one.
- **The model says which thing, and which words. Code says the rest**: which way, how much, how firm, by what way of travelling, and whether the thing may be offered at all. Four fields of an answer are not read: `direction` on a thing that runs one way, `value`, `strictness` and `provenance`. They stay in the shape, because taking one out changes what a model answers.
- **Thirteen checks stand between an answer and an offer**, numbered as the contract numbers them, in `guard.py`. Each has a test made of an answer a model gave, which is on disk in `evals/reader/answers/`, and what each costs is held beside it.
- **A model chooses the words it quotes.** So nothing that makes an offer stronger is read from the quote alone. What makes a limit firm, how much a wish counts, the way of travelling, what turns a wish round and what a number is a number of are each read where the number or the thing stands, as core finds it. A limit is firm by core's list for its kind, `FIRM_OF_MONEY` or `FIRM_OF_MINUTES`, and a journey is firm too at the longer end of a range the person typed, and never at the shorter. `tests/test_adversary.py` holds answers written to get a wrong reading past each check: a quote so wide that it holds what was said of another thing, and one so narrow that it leaves out what turns the wish. A new check gets a case there.
- **What is said about a thing is read where the thing stands.** A guess is never marked where the words about the thing turn the wish round, or give it to someone else: "a station, heaven forbid", "my mum is after a park". `typed.about` and `typed.anothers` read the sentence where core finds the thing and where the model's words stand, across the marks either side, and never what a model says it quoted: the words that turn a wish are the ones a model leaves out. The thing is still offered, as a question, with the whole of the sentence shown. Both are checks of a wish that a model read: what the rules alone noticed is offered as it was, and a journey is nobody's wish. Every word is core's: `DREADS`, `WHO_ELSE`, `WISHES_OF_ANOTHER`, `STANDS_FOR`.
- **A guess on a scale takes the end the person named.** `typed.ends_named` reads which end the words of the clause name, each with what leads up to it: an end that is turned away is a wish for the other, as the rules read it, so "houses not flats" is Houses. The model's end is the guess only where the words name it, and where a model named no end the guess is the end the words name only where they turned one away. Two words that turn before an end name none, and a word for a home alone names none.
- **What is never offered from a model** has a test for each row: a vibe that counts recorded crime, recorded crime the words do not name, anything about who lives somewhere or that rests on a community's amenity, a measure or a vibe that counts who lives somewhere, a reading of a word the rules offer what is nearest for, a firm limit nobody gave, a least distance as a journey, a number for a weight, a place or an amount the person did not type, a number typed as another kind, a way of travelling nobody named, an end of a scale no phrase of core's names, a rule for an area as a guess. **Core lists no word about wealth or about identity yet**, so a model's reading of "affluent" is offered: the two tests of it are expected to fail until core lists the words.
- **Whatever the rules offer is kept.** A word the rules offer what is nearest for, with a note of what Burro cannot measure, is the rules' to offer, and a model's reading of the same words is dropped. So is a model's reading of the same thing on any other words: a thing the rules offer with a note is served as the rules give it with no model, with no guess marked. It is held on every phrase of core's lexicon that carries a note, so a word core adds is held to it the day it is added.
- **The words of an offer are written for a person who has never seen Burro**, as [the guide to the words](../../docs/design/words.md) asks. What an offer would do is a whole sentence that says what an area is or has where it ranks higher, "Rank an area higher when it is nearer a park.", and a measure whose two ways each have a word of their own, "dearer", says what the word is of: `WHEN` in `wording.py`, which a test holds to every such measure. No part of an offer, and no message of a failure a person can meet, says a release, a recipe, a part of one, a spec, a route or the contract. A message promises no way of telling Burro of a fault: the website has none.
- **The words of an offer are the API's**, made in `wording.py` from the edits and the catalogue. No part of an offer holds a word the person typed. The person's own words are served as where they stand, and a client cuts them from the text it holds.
- **The same readings make the same offers.** `merge.py` puts the readings in the order of their words before it makes anything of them, and the offers in the order of their first word. Nothing that is served rests on the order in which a model wrote its edits. Do not read a model's answer in the order it came in.
- **Who lives somewhere is the rules' to offer.** Core offers a phrase for those who are counted, by their age or their households, towards more and with a note. A model is told of no such measure and no such vibe (`reader._vocabulary`), an edit of a model's that names one is dropped under check 13, and what a model reads into the words the rules offer one for is dropped as a reading of any word with a note is.
